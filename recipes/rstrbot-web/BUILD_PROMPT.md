# TypeScript / React Web 工作台

实现可独立部署为静态资源的TypeScript前端，采用当前React路线；核心和SDK语言保持，辅助工具可选择。依赖 `service` 提供同源真实API与测试进程，归档内 `.deps/service/`；前端开发时需要它验证认证、权限、数据与副作用，生产浏览器无需装Rust/Node。依赖中的schema是表单和状态的事实来源。

读 [DESIGN.md](DESIGN.md) 与 [WORKFLOWS.md](WORKFLOWS.md)。所有当前源流程与上一轮未提交的视觉/教程改动都须保留。未来实现可重设内部组件，但不得用静态界面、假回执或固定样例替代真实业务。

## 导航和阅读

左侧栏/顶栏两种可切换布局持久保存偏好，当前工作区、页面和权限过滤一致。桌面顶栏按工作、知识与代理、连接、工作区管理、账号、开发者分组菜单组织；中等宽与手机采用抽屉。侧栏与会话列表各自可折叠，按钮有label/expanded。自动收起依据实际滚动位置与用户方向、阈值和迟滞，避免抖动；手动偏好与自动状态分开。输入聚焦、弹窗或菜单操作时保持控件可用，不抢滚动或丢失聊天锚点。

## 数据与表单

所有API请求按用户/工作区/会话键隔离，切换取消旧读请求并忽略迟到结果，已提交写入不因卸载伪报取消。401清认证缓存，403/404清对应访问缓存；重新登录换用户不可看到上一人私有数据或草稿。模型输出只作安全文本；坏历史逐条跳过、稳定ID去重，终态不能被迟到delta复活。

模型和渠道按身份/连接、凭据与限制、确认分步。模型provider从已安装且声明`model`能力的插件真实枚举，不硬编码openai/diagnostic清单；声明能力不代表一定实现`model.list`。模型ID默认可手动输入。插件支持`model.list`时，可在配置向导调用核心发现API，把最多500个真实ID作为输入建议；保留键盘输入，不强制从建议列表选。展示加载、失败、空列表、夹具和截断状态；发现失败时仍可保存手填ID。发现只请求提供方模型列表，不执行生成或预留RstrBot模型预算，需说明提供方仍可能记录请求或计费。新密钥仅随本次发现请求发送，不写入浏览器持久草稿、日志或数据库；复用已保存密钥前，必须确认工作区模型、provider、完整地址和私网授权一致，改变provider/地址时不得把旧密钥转发给新目标。发现调用撤权后停止，不得继续调用插件。浏览器请求绑定当前表单目标，改provider/地址/凭据/私网授权时取消并忽略迟到成功或错误；关闭、切工作区/用户/资源时清理。读取期间提供取消等待按钮，不把取消等待说成供应商已停止处理。用白名单构建保存请求，不回传只读状态/has_secret标志；同一完整目标保留秘密，变更需替换/清除。模型测试显式说明真实调用与费用可能未知。渠道当前只列Webhook，无无副作用测试接口就不显示假“测试成功”。

模型与渠道向导在离开每一步前校验该步字段，复用最终提交的UTF-8字节、URL、密钥绑定、整数token和精确微美元规则。字段错误与label、控件和说明关联，聚焦首个错误；最终服务端失败仍保留草稿。Enter在核对前只前进，核对后才保存；保存期间禁用重复提交和关闭入口。

Webhook保存、授权、启用、发送不同状态。继续原POST使用同key仍可能首次发出请求，不能称为只读查询；新的发送必须先确认核对过目标结果。URL、费用、token、文本按服务UTF-8与整数约束；小数微美元转换避免二进制舍入。

## 1.11 明确的修复方案

提示词原子存储记录以实例来源/认证用户为键；旧匿名数据保留原键且不读取/展示/导出，不自动认领，教程说明升级规则。成功登录/退出跨标签页通知后清理旧界面。时区建议来自浏览器实际IANA目录，核心preview最终验证；每日/每小时预设与自定义共存，预览和保存共用白名单及字段校验。传输失败用当前语言说明未知结果、保留草稿，提供只读记录核对，技术原文折叠，用户手动继续保留幂等意图。

## 1.13 可重建完整工作台

必须同时实现 [CAPABILITY_WORKFLOWS.md](CAPABILITY_WORKFLOWS.md) 中的可观察合同，保留当前接口、权限与历史验收。新增能力按服务/协议协商实际开放，未实现保持不可用；配方升级不产生新的软件通过证据。新增验收见该文件并与本包原验收逐项运行。

## 1.14 上游拒绝的单语言恢复提示

依据核心安全错误码，而不是匹配上游原始文字，分别提示模型认证、权限、限流及其后续操作；对话失败后和重开历史均可读，认证/权限提供模型配置入口；中文只显示中文，英文只显示英文。其他插件与未知码使用通用安全提示，网络不确定时沿用原有核对流程，不自动发送。

## 1.18 会话模型绑定

按当前会话恢复最近接纳模型，不因增加模型、导航、刷新或重启自动切换。旧记录缺绑定以及模型删除/撤权时必须明确选择后才能发送；迟到读取不得覆盖手动选择。 与根 RSTRBOT-24 一致；本地实测范围与未测反例见根测试记录。

## 1.19 长草稿重排

按根 RSTRBOT-25 保持内容、选区、焦点与用户自主滚动：正在编辑且原本可见的插入点在尺寸变化后可见，阅读者手动滚动不能被强制拉到底；检查输入法和正文滚动不受影响。

## 1.20 未确认发送

执行根 RSTRBOT-26：隔离并持久化完全相同的发送请求及幂等标识，刷新和导航后明确显示待确认；必须核对后手动继续或明确放弃旧意图再创建新意图，不自动发送，不误清新稿。浏览器持久化不可用时要明确降级。

## 1.21 多标签页协调

按根 RSTRBOT-27 在同源浏览器协调同一用户/工作区/会话的意图读改写与清除，确认框绑定确切记录并拒绝过期确认；变更通知其他标签页，不支持协调时说明且安全暂停。

## 回答中的资料核对

执行根 RSTRBOT-29：候选来源与模型实际引用区分；按当前权限获取来源并比较摘要、索引版本、分块与 UTF-8 字节区间，匹配才展示原文及命中片段。旧版本、失权、停用、删除、异常或失联不展示旧缓存冒充可核对结果，关闭或身份/会话切换清除视图，迟到响应不能回填。

RSTRBOT-32：对知识索引不一致的失败运行提供当前语言的原因、受众获准查看的问题资料名称和重新保存文档的修复方向，不以普通空答案或通用供应商错误代替。

RSTRBOT-33：计划列表和详情以当前语言展示最近运行结果及待核对状态，提供有权运行记录直接入口；说明未知请求不能自动重发。不得将 disabled 一律解释为已暂停或把历史 failed 描述成成功。

RSTRBOT-34：待核对计划显示核对入口，确认前说明旧结果可能未知且确认不会重发；有运行时可查看、没有运行时说明不可核实。确认后显示暂停及独立启用操作，过去的一次性计划提示修改未来时间。

RSTRBOT-35：重选当前工作区不取消当前授权读取；切换不同工作区仍隔离旧缓存和迟到结果。对延迟模型详情读取做实际浏览器发送和下游运行验收。

## 投递意图恢复

遵循根合同 RSTRBOT-37：发送前持久保存用户/工作区/渠道隔离的意图并协调标签页；存储或锁不可用、旧状态冲突时停止发送且保留草稿。结果未知时允许用户核对后显式创建新意图，不因创建草稿发送；旧请求的原编号和回执不被覆盖。保留并安全迁移旧版 sessionStorage 未决意图。

交互及运行记录按结构化错误码显示工具目录超限、插件包缺失和无效目录的当前语言原因及修复方法；禁止把安全通用错误伪装成完整目录。

## 会话文本附件
