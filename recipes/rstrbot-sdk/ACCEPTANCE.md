以下是未来重建必须执行的验收方案。本次迁移未执行这些软件场景。每项使用独立临时数据与测试账号，记录平台和结果。

| 编号 | 输入与操作 | 预期结果 |
| --- | --- | --- |
| RSTRBOT-SDK-01 | 构建 Rust echo，运行共同协议向量 | 初始化、发现、Unicode、通知、错误及非法凭据均按 protocol 一致 |
| RSTRBOT-SDK-02 | 分别以 Python、TypeScript、C# 真实进程运行同一组向量 | 各语言逐项给出结果；缺运行时为 not_executed |
| RSTRBOT-SDK-03 | 四个示例各处理一个等待调用，分别发 cancel、截止超时和断开 | 取消传递，无后续正常成功；资源在有界时间内回收 |
| RSTRBOT-SDK-04 | Python 列出含有导入副作用的入口点元数据 | 不执行模块；明确指定唯一名字后才导入；重名失败 |

## 1.13四语言能力验收

合同位置：[SDK_CAPABILITY_CONTRACT.md](SDK_CAPABILITY_CONTRACT.md)。以下每行必须分别执行Rust/Python/TypeScript/C#真实进程，共同输入与oracle相同；结果表保留每语言每平台单元格，当前全部`not_executed`，缺运行时不能以其他语言代过。只有合成账号与本地受控服务，不发送真实消息/商业请求。

| 编号 | 操作/故障 | 验收断言 |
| --- | --- | --- |
| R13-SDK-001 | 跑protocol原1.0和扩展PX-V01..12，附四语言SDK版本/启动命令 | 原向量保留；扩展feature/错误相同；不兼容失败在业务调用前 |
| R13-SDK-002 | 同一Unicode/UTF-8限额、整数边界、null/缺字段、decimal费用与opaque状态往返 | 字节摘要和语义一致；不截断/补零/丢供应商签名；超限分类相同 |
| R13-SDK-003 | 快速发进度/慢消费/重复终态/错request_id | 有界背压或slow_consumer；每root只一个终态，无静默丢数据 |
| R13-SDK-004 | handler等待、host服务等待及写入接受后分别取消/截止/断连 | 取消穿透异步任务，cleanup有界；真实进程/句柄收回；已知回执保留且下游不重发 |
| R13-SDK-005 | 真实读资源→核摘要，数据CAS并发冲突，凭据broker固定受众；改目标/撤权 | 四语言返回相同字节/冲突/拒绝；秘密不进普通工具或stderr；重启旧柄不可用 |
| R13-SDK-006 | 注册hook/parent-command/alias，变顺序、参数、权限和generation | 真实hook记录顺序一致；父过滤生效；别名冲突可见；B实例收到A内容0 |
| R13-SDK-007 | 各语言跑模型稀疏流、媒体读取、平台接收/发送、MCP工具调用；回执前断线 | 工具ID/引用/usage不丢失；下游数据可读回；unknown不自动重放 |
| R13-SDK-008 | task.submit后断开worker、重启核心；父取消/预算不足/降权 | 已提交child_run_id可查；未提交不伪造任务；无隐式孤儿进程；子权限不扩张 |
| R13-SDK-009 | 无Python/Node/.NET启动Rust；Python含导入副作用入口的--list；冲突依赖两个实例 | 核心可用；只读发现导入计数0；缺运行时明确；实例依赖/配置/数据不混用 |
| R13-SDK-010 | 干净环境按四语言教程走创建→授权→调用→取消→恢复→卸载，核机器索引 | 每公开能力对应schema/示例/错误/验收；样例真实下游可核；缺项保持未完成 |

SDK文档/索引校验与运行验收分开记录。源码可编译、包可打包或基础echo通过，均不能替代完整扩展功能证据。
