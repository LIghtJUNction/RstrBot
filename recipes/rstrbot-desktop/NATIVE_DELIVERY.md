# 1.13 原生交付、更新与恢复合同

这是未来原生实现/验收合同，不是安装器回执。现有 `DESKTOP_REFERENCE.md` 是来源快照：三平台原生安装、签名和升级均未本轮执行；Windows本机worker仍为未支持。依赖 `client` 及其递归 `service` 提供完整Web和核心；不另写身份/预算/插件/投递逻辑。

## N01 模式、输入和数据归属

| 模式 | 输入和结果 | 权限与取消/失败 |
| --- | --- | --- |
| 本机 | 当前平台/架构匹配且摘要校验通过的核心、worker和Web；用户选择系统数据目录或显式便携目录→本次子进程、锁、loopback origin与工作区窗口 | 只打包launcher可启动；启动取消回收本次拥有的进程；失败保留数据/密钥且返回真实阶段，不连接恰好占端口的其他HTTP服务 |
| 远程 | 用户显式提供HTTPS根origin→受该origin认证的工作区窗口 | 拒绝URL用户密码/查询/fragment；无本地核心和业务库；关闭窗口不取消远程计划，也不修改服务器配置 |

同一数据根只能由符合核心部署模式的一个本机实例持锁；锁争用显示现有实例冲突，不删除锁文件强行接管。数据根不随cwd变化；用户变更目录须停止写入、校验复制后的归属/对象/摘要并保留原目录至核对完成。安装目录、用户数据、秘密和临时缓存分别管理。平台不支持本机transport、系统运行时缺失、签名或摘要不符分别报错，不能自动退回无隔离进程。

## N02 生命周期与原生边界

逻辑状态为 `idle → validating → starting → ready → stopping → stopped`，任一步可到 `failed`；这些是launcher状态，不能覆盖核心run/delivery终态。开始前校验所有目标产物；ready必须来自本次受控子进程的真实启动标记并与本次启动上下文关联，不以端口可连接作证明。端口争用重新给出错误，不把用户引到无关服务。bootstrap证明只向本地受信任launcher提供，不能进入URL、日志或远程WebView。

关闭本机窗口按既有默认发出有界正常停止，当前来源12秒强停边界保持有据；新平台实现须分别证明所属完整进程树回收。强制结束后核心恢复使用持久事实：未派发、已接受、unknown分开，未知外部操作不自动重发。系统强杀/断电不是正常退出成功。用户选择仅隐藏窗口时须显示核心仍在运行；不得含糊把隐藏等同退出。

workspace页面不具有shell、文件、启动/停止、更新原生命令。launcher除固定本机启动、远程连接、断开及未来受授权更新外无任意命令入口；Rust侧再次检查调用窗口、打包origin及参数范围。远程内容导航受选定origin约束，外部帮助链接通过清楚的用户动作交给系统浏览器，不携带凭据。TLS错误显示诊断，不提供默认忽略证书。Tauri capability只控制授予的原生API，不宣称能替代内容/网络沙箱；依据 [Tauri capabilities](https://v2.tauri.app/security/capabilities/)。

## N03 安装、升级、回滚、卸载

未来更新清单必须含版本、目标OS/arch、包摘要、签名及签名身份、最低兼容schema、变更摘要；由固定可信来源获取，更新来源/信任根变化是独立授权。签名方案/分发服务和账号当前未选定，默认自动更新关闭，不能造签名通过。下载取消只清本次临时包；失败不替换可运行旧版。

升级按 `downloaded → verified → staged → quiesced → backup_verified → activated → health_checked` 记录可恢复状态。先停新任务并等待或明确中断现有运行，校验一致备份及单独密钥保护；跨schema升级使用core/store迁移合同。健康失败只有二进制与数据schema均向后兼容才回旧二进制；否则保持恢复隔离，用已验证的旧版备份显式恢复，不能让旧程序写新schema。中途断电重启依据升级日志选择唯一代次；保留unknown投递和未决费用，不以回滚抹账。

卸载默认只移除安装文件；删除数据须独立选择准确数据根并说明数据库、密钥、插件外部状态的后果，不能扫描其他工作区/远程服务器。取消卸载保留当前状态；部分删除失败列逐路径结果和仍保留数据，不能宣称清理完整。诊断导出默认只有版本/状态/脱敏错误，不含数据库、Cookie、真实聊天或秘密。

## N04 平台与发行门槛

| 平台范围 | 当前证据 | 新验收前提与门槛 |
| --- | --- | --- |
| Linux本机/远程 | 来源有核心与静态桌面检查；原生安装未执行 | 冻结发行版/arch/WebKitGTK/桌面会话；实际安装启动、权限、退出、升级/卸载和只读结果核对 |
| macOS本机/远程 | 原生未执行 | 冻结macOS/arch/WebView及工具链；实际系统权限、签名/公证条件、子进程与安装升级 |
| Windows远程 | 原生未执行 | 冻结Windows/arch/WebView2；安装、远程origin隔离、退出与本机零业务库 |
| Windows本机 | 当前unsupported_platform | 先证明named pipe ACL、命名防抢占、完整进程树回收、四SDK与文件权限，再允许本机入口 |

最低OS、CPU架构支持矩阵与商业签名账号待确认；可在测试记录选择实际可用环境作为候选，不把候选当支持承诺。平台包名必须来自真实目标产物；更改文件名不算交叉编译。CI配置存在、静态check、打包成功、原生安装、外部服务连接、公开发布各有独立结果。此次任务禁止触发CI/发布，未来发布流程仍需另有授权。

## N05 新增验收

每项逐平台逐模式记录 `not_executed/passed/failed/blocked`；以下初始均not_executed。

| 验收ID | 过程及可观察断言 |
| --- | --- |
| R13-DESKTOP-001 | 干净环境安装真实目标产物→本机首启→真实只读模型/工具对话→重开历史。核对child身份、数据根/锁和下游结果；缺任一前提不能打“原生通过” |
| R13-DESKTOP-002 | 在启动标记前抢占端口、子进程崩溃、取消、摘要损坏；另有无关HTTP服务。launcher不得打开无关端口，资源回收有记录，原数据不变 |
| R13-DESKTOP-003 | 远程HTTPS连接后诱导网页调用原生命令/打开恶意origin/下载本机秘密。拒绝；远程运行正常且本地无新核心/业务库；断开不停止服务器任务 |
| R13-DESKTOP-004 | 活跃worker及其子进程下正常退出、强杀、OS重启各测；权限撤销与关闭竞争。只回收所属树，下一启动run interrupted/unknown可核对，目的端计数不因重启增加 |
| R13-DESKTOP-005 | 各升级状态点断电/磁盘满/签名不符，测试schema兼容与不兼容回滚。最多一代激活，旧数据/备份保留，不以旧二进制打开新schema |
| R13-DESKTOP-006 | 默认卸载、显式删测试数据、取消与部分失败；不同数据根/远程实例并存。只处理选择的范围，未选数据仍可重装读回，无自动删除秘密目录 |
| R13-DESKTOP-007 | Windows本机能力缺失时拒绝；未来完成pipe ACL/命名冲突/进程树/跨SDK后再开放。静态与原生证据分别记录，不能继承Linux通过 |
| R13-DESKTOP-008 | zh/en、窄窗口、键盘、200%缩放、系统减少动作；更新/恢复失败保持语言和可达操作。截图之外记录实际屏读/设备与未执行项 |
