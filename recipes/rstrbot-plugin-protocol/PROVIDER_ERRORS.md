# 模型提供方拒绝：1.14 补充协议向量

这是协议 1.0 的可选错误分类，不改变握手、消息形状或原有参考和向量。只有 worker 实际收到对应模型上游 HTTP 状态时，才可用以下 JSON-RPC 错误码；不读取、不返回响应体、认证信息或其他秘密。

| 上游状态 | JSON-RPC `error.code` | 核心安全分类 |
| --- | --- | --- |
| 401 | -32041 | `provider_authentication_failed` |
| 403 | -32043 | `provider_access_denied` |
| 429 | -32029 | `provider_rate_limited` |

兼容向量：Rust、Python、TypeScript、C# SDK 各自发送相同请求 ID，分别返回上述三种整数代码和固定非敏感消息；新宿主识别代码，不信任原始消息；旧宿主将未知代码视为普通远端错误并继续终结调用。`-32000`、未知代码、超时和断网不可误判为已收到特定状态；无自动重放，不将未知费用写成零。SDK 至少保留整数 `code` 与同一请求 ID，不依赖本项目核心内部类型。实际进程互通和四运行时没有逐一执行时分别标为未执行。
