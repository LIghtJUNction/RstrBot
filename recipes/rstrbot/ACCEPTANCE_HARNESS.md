# 1.13 验收执行约定与最小夹具

验收本质是：给程序一个已知输入，在出错、取消或重启的交界停一下，再检查数据库事实和真正的下游效果是否一致。仅有UI提示、HTTP 200、协议握手或文件打包成功不足以证明业务完成。

本文是未来生成实现必须交付的测试要求；本轮仅校验配方材料，未运行RstrBot软件或竞品。全部新增软件场景初始 `not_executed`。当前本地实现的历史回执仍以CURRENT_SCOPE/SOURCE_EVIDENCE为准（1.11，34 Web＋11新增及7原浏览器场景）；它们不能自动计入1.13。

## H01 记录与结果类型

每个验收条目至少记录下列字段，可保存Markdown内JSON对象；配方中仅保留脱敏合成数据的精选回执，原始运行日志放操作者选择的测试输出目录，不固定 `artifacts/`。

```json
{
  "case_id": "R13-RB-029",
  "contract_version": "1.13",
  "phase": "runtime",
  "status": "not_executed",
  "implementation_commit": null,
  "binary_sha256": null,
  "environment_id": null,
  "fixture_seed": "r13-synthetic-01",
  "input_digest": null,
  "commands_or_ui_steps": [],
  "fault_point": null,
  "expected": [],
  "observed": [],
  "downstream_receipts": [],
  "evidence_paths": [],
  "started_at": null,
  "finished_at": null,
  "blocked_reason": null
}
```

`passed`仅在预定断言实际执行且有结果时使用；`failed`表示运行后违反合同；`blocked`说明环境/授权/设备不足；`not_executed`表示没运行。能力另外记 `implemented/partial/not_implemented/unknown`，无法运行对方不算失败；RstrBot未实现算功能缺口，不能用not_executed掩盖。配方静态检查使用 `phase=recipe_validation`，永不提升runtime结果。弃测、超时和失败样本不能从性能分母中删掉。

## H02 合成对象与最小真实下游

创建独立临时数据根/数据库schema/端口，安装前检查目标为空且非现有服务。测试账号为A（owner）、B（member）、C（viewer），另有不属于工作区的D及只持实例运维权的O。工作区W1/W2建同名资源；A/B在W1各有私有会话PA/PB和明确共享会话S。每一私有对象放可识别哨兵 `SYNTHETIC-W1-A-PRIVATE`，用API、下载、事件、检索、导出、日志和浏览器存储核对不得泄露。所有身份仅为临时合成账号，不使用真实用户消息或现有凭据。

| 夹具 | 必须能观察/控制 | 用途与证据限制 |
| --- | --- | --- |
| 模型HTTP/SSE服务 | 记录每次请求ID、有效参数、流首块/结束/工具调用、接受后断线；返回确定文本/usage未知 | 验证真实HTTP和进程链；内容用合成数据，不能算商业模型质量 |
| 只读工具进程 | 四SDK各从独立进程读固定合成文件并返回其摘要/内容；可卡住、崩溃、超大帧 | 握手不算调用成功；必须读取工具下游实际文件值和进程退出 |
| 投递接收端 | 接收计数、意图ID、目标ID、可在接收之后丢确认/在返回之后阻断存储 | 用来证明accepted、unknown和不重复；不能算真实聊天平台验收 |
| 平台入站适配器 | 合成事件ID/原渠道/账户/群/用户/线程/引用/回声/重连顺序 | 观察消费游标、运行、发件目的地；测试适配器与真实平台分开 |
| 对象与索引服务 | 可读回字节摘要、分片/版本、索引代次、旧引用、延迟提交 | 媒体、知识、附件与备份一致性；检查权限前置而非只检查隐藏按钮 |
| 数据库与网络故障层 | 可按事务阶段拒绝写入、磁盘满/锁等待、连接断开、只读模式、缓存中断 | 故障注入只限临时实例；不修改真实系统网络/生产库 |
| 时钟/调度控制 | 冻结UTC、调整墙钟、保留单调截止、指定tzdb、重启/两执行者竞争 | 不靠长时间睡眠猜发生时刻；真实预览和执行共享同一时间函数 |

当前可用CLI严格以递归core的CLI.md为准；不凭本文件发明现存命令。重建者需生成这些夹具和自动化入口，并在运行记录填实际命令/版本；不存在的测试工具不能记通过。

## H03 七种边界必须逐能力检查

1. 成功：从用户入口提交，经实际服务/worker到下游，重新读取对象/事件/账本，再刷新/重开；确认内容和归属，而非只检查状态码。
2. 失败：输入错误、服务拒绝、进程失败、持久化失败分别注入；错误可定位且无假成功、无未授权替代路线。已观察到下游成功仍须保留，不能统一改成“未执行”。
3. 取消：排队、准备、等待模型/工具、已提交外部请求之后逐点取消；只承诺不启动后续阶段。已接受外部效果不能被取消抹去；慢钩子不能吞取消并启动fallback。
4. 重启：认领前、意图持久化后派发前、下游接受后回执前、回执后投影前分别终止核心；恢复后唯一意图与真实计数相符。unknown保持核对态，连续重启也不能丢记录或补发。
5. 权限隔离：A/B/W1/W2/O以及同账号两个不同会话并测；所有授权来自服务端当前状态，不信任客户端scope、ID字符串或声明能力。管理员没有隐式私人内容读取权。
6. 撤权：在排队后、握手后、发送前、在途与返回前移除成员、停插件、撤凭据/授权；检查旧租约失效、后续执行为零、迟到结果不向已失权UI泄露。新的同账号会话不能续命旧交互意图。
7. 预算/副作用：并发先预留，unknown使用/价格不为零；每个模型实际尝试、工具效果、投递和费用逐条对应。生成成功、外部接受、保存成功分列；副作用数量不能因重启/重试/切模型/跨会话兜底增加。

CAPABILITY_COVERAGE每条的R13-RB场景均包含以上边界的具体断言。仅纯只读/装饰能力的“预算或副作用”应断言无模型、无外发、资源有界，而非填写不适用跳过。

## H04 故障窗口与读回证据

| 故障窗口 | 需要保存的事实 | 恢复断言 |
| --- | --- | --- |
| 尚未提交意图 | 验证/拒绝原因；不得消耗新幂等意图/预算 | 可修正后发起新合法请求；零下游效果 |
| 意图提交、尚未派发 | owner/scope/配置版本/授权/目标及意图ID | 最新权限仍有效且明确未派发才允许按合同继续；否则blocked/cancelled |
| 请求可能离开进程 | 派发attempt、租约/fence和目标 | 没有确定否定证据记unknown；不自动fallback到其他模型/路由/会话 |
| 下游已接受、回执写失败 | 接收端凭据化可核对记录、已知accepted事实与本地保存失败 | 不为了“任务重试”再发送；恢复只读核对并补事实，无法确认保持unknown |
| 回执保存、UI确认丢失 | 持久ID/序号和幂等键 | 同意图返回原记录；迟到确认不清用户新草稿 |
| 恢复/升级后 | 恢复代次、schema、插件/对象清单和未决记录 | quarantine期间模型/平台/计划不派发；显式核对后也不自动重放unknown |

“数据库未见记录”不是“外部一定没发生”的证据。要证明最多一次外部效果，必须同时记录意图唯一性与下游接收计数；没有可靠目的端核对只能保留保证范围。

## H05 测试矩阵与分层执行

服务端共同业务场景在SQLite/PostgreSQL × Valkey关闭/正常/中断执行；缺PG环境就记blocked，不用SQLite通过代替。四SDK按当前1.0共同向量及未来协商向量逐语言运行；Windows本机先过transport/ACL能力门槛。Web按CAPABILITY_WORKFLOWS的语言/主题/视口/键盘矩阵；桌面按NATIVE_DELIVERY逐OS本机/远程记录。媒体、群聊、MCP、兼容、子代理、编排、多节点未实现时必须出现在矩阵并标gap。

竞品采用COMPETITIVE_RUNBOOK的冻结版本、12任务与同条件控制。真实模型质量、诊断流程、供应商费用、平台限制和人类体验各自报告。性能记录PERFORMANCE要求的设备/负载/失败样本；预算数字未知，不能填虚构通过阈值。1 vCPU/1 GiB只是待测候选，不是当前测试机证明。
