# 核心领域完成合同 · 提示词 1.13

本文件把未来能力落实为可以生成和验收的行为。它**不改变当前实现状态**：r2 的 API v1、66 个业务操作和 2 个健康操作由 `OPENAPI.md` 与 `HTTP_CONTRACT.md` 独占定义；这些当前接口保持兼容。服务身份、受限凭据代理、写工具审批、子代理、群聊、通用媒体、索引换代、编排和多节点等新增行为均为 `specified / not_implemented / not_executed`。已有部分实现也必须重新执行本文件对应场景，历史回执不能充当本轮通过。

未来 HTTP 操作、DTO 和协商只在 [EXTENSION_API.md](EXTENSION_API.md) 定义；持久状态与恢复使用 `storage` 依赖的 `DURABILITY_CONTRACT.md`；插件线协议使用 `plugins → sdk → protocol` 中的 `EXTENSION_PROTOCOL.md`。本文件规定业务含义，不复制 OpenAPI 或上游 SDK 源码。

## 共同执行规则

一次业务动作本质上是“检查当前权限 → 保存意图 → 执行一次 → 保存实际结果”。不能把网络超时等价为未执行。

- 所有入口先构造核心拥有的 `AuthorityContext`：实例、工作区、主体、原始交互凭据或持久委托、资源授权版本、截止时间、预算引用、可用能力。客户端和插件提供的身份字段只能是待验证目标，不能覆盖可信上下文。
- 资源默认 private；共享运行只能消费向同一受众公开的资源。HTTP、CLI、MCP、SDK、计划和兼容入口都调用同一领域操作，不重复实现较宽松的业务权限。
- 每个外部调用在准入、队列出队、插件握手后派发前重新核权；在途有界监测撤销。撤销能禁止后续动作，不能保证撤回已被远端接受的动作。已知用量和已知回执仍记账，结果读取再检查当前 ACL。
- `execution`、`delivery`、`persistence` 独立；`completed` 不能代替平台接受或落库成功。终态、用量、失败原因、可恢复动作均有稳定编号，UI 依据事实显示部分完成。
- 所有异步工作保存对象版本、运行 generation 和请求标识。旧代事件只能进入其原审计，不覆盖新会话、新配置或已删除对象；游标过期显式返回 resync_required，不偷偷从最新位置继续。
- 取消向子任务、插件、索引/媒体任务传播，并有有界进程回收；已发布对象不因取消清空。重启依持久事实恢复；所有 sending/unknown 外部操作默认核对、不自动重放。设计允许安全重做的纯读取也必须重新取得当前授权和显式的新 attempt。
- 预算、并发、字节、解码、步骤、深度、尝试次数和截止时间必须有有限有效值。限值可由管理员降低，缺少有效上限时相应能力 unavailable；不得靠无限队列或无限重试通过验收。

## D01 身份、工作区与授权（RB-002/003/004/007）

输入是已验证账户、目标工作区/资源和明确动作；输出是最小可见对象或稳定拒绝。身份页不要求工作区。首次初始化仍使用本机短期证明、原子创建管理员/工作区、最后所有者保护。数据库选择和探测不修改已初始化数据库；取消选择保留原配置，探测成功不代表已切换。

未来扩展采用以下最小权限矩阵。此矩阵只约束新增操作，不能放宽 v1 的现有权限判断；不满足任一资源所有权/授权条件仍拒绝。

| 主体 | 可读 | 可写/执行 | 禁止与恢复 |
| --- | --- | --- | --- |
| viewer | 获准的 workspace 可见资源与脱敏运行状态 | 不创建运行/资源，不审批、不投递 | 旧编辑按钮也必须后端拒绝 |
| member | 上述及本人 private 资源 | 创建/编辑本人资源；运行本人或明确授权资源中的只读能力 | 无全局安装、成员管理或他人私有读取 |
| operator | member 范围及被授权运行信息 | 对明确获准的共享运行/路由执行与停止；不能替换别人计划的意图 | 操作许可不包含读取他人私聊或修改权限 |
| admin | 管理工作区公共配置、成员和共享对象元数据 | 插件实例/配置管理；按规定删除共享计划；显式给服务身份授予工作区能力 | 不能修改他人计划的所有者意图，不能隐式获得 private 内容；不能移除最后 owner |
| owner | admin 范围 | 转交所有权、修改工作区边界；涉及删除/外部费用须明确操作 | owner 也没有其他用户 private 资源的隐式读取权 |
| 实例管理员 | 实例设置、安装/网络政策、脱敏诊断 | 可信包安装、本机恢复、实例升级 | 未成为工作区成员不能获得业务写权；运维数据访问走独立本机恢复边界并记录 |

个人 API 凭据是未来独立类型，不与当前 Bearer 会话混淆。个人凭据绑定账户、显式 grant、到期时间和版本；有效权限为“账户当前权限 ∩ 凭据 grant ∩ 资源策略”，降权即缩权。服务主体不冒充人类，绑定单一工作区、显式资源/操作 grant、负责人和单独凭据版本，不由创建者的浏览器会话续命；其配置撤销、成员政策或服务状态变化立即约束运行。后台委托必须明确主体、目标、最大持续时间、预算和可撤销引用，不能把个人交互 run 偷换为服务 run。

分页、计数、搜索、媒体链接、事件、缓存、导出与审计都在读取时授权。没有读取权时返回同一 not_found 表面，不泄露资源是否存在。成员移出后，已缓存授权内容隐藏且迟到请求不能重新显示；重新获准后须成功读取才能恢复。普通审计只给动作/对象标识/状态和必要元数据，不含私聊内容、凭据或原始供应商响应。

资源分享是单独版本化动作，明确受众和资源集合；改变父会话分享不自动公开子附件/记忆/私有代理。撤销分享使新的读取、下载、导出和运行引用立即失效；已经下载到外部客户端的数据无法追溯撤回，必须真实说明。

验收：`R13-CORE-001/002/003/004`，存储 `R13-STORE-001/002/003`。

## D02 配置、人格与凭据（RB-005/013/024/041/050）

配置输入必须携带对象版本；输出包含 `effective_value`、来源层、配置摘要与未满足前提。默认继承顺序为实例允许值 → 工作区 → Agent/人格 → 会话 → 本次运行显式覆盖；子代理只能在父授权和父预算内覆盖。每层用 `inherit / value / clear / disabled` 四态：inherit 向上找，value 取本层值，clear 产生类型允许的空值，disabled 禁用能力。空字符串不能偷偷表示 inherit；不允许 clear 的必填字段返回 validation_failed。授权及强制上限按交集/最小值求有效值，不能被下层扩大。

运行准入时冻结有效模型、人格、示例、工具清单和配置版本。配置更新只作用于新运行；在途若相关权限被撤销则停止后续调用，但不把新人格拼进旧运行。示例具有 `example` 来源，不能写为真实对话；临时提醒归属本次运行并受总字节上限，不永久追加到历史。导入人格先只读解析、显示字段/冲突差异，再用 CAS 明确新增或替换；解析失败/取消保留现有对象和本地草稿。

新增供应商 B 是创建独立 ID 的操作，不能以名称或模型字符串覆盖 A。保存前校验重复 ID 与显式替换意图；发现列表是来源标记的建议，空列表/不支持发现保留自定义模型 ID。可连接、可发现、可调用三个测试状态独立。模型测试只使用保存配置，可能收费，不能把发现成功当生成成功；临时发现凭据不持久化。

凭据引用绑定 `(workspace, principal, provider, canonical full endpoint, scope, revision)`；目标的 scheme/host/port/path 变化都需新凭据或显式清除。受限凭据代理只向获准 worker 给短期 opaque handle：操作、目标、账户、到期、预算引用固定；认证注入/刷新/签名由独立受信组件完成。普通工具、知识文档、兼容插件和日志拿不到原密钥。代理注入与受信签名各需独立验收，不能因为包声明支持就标为可用。

OAuth、刷新和轮换状态为 pending → verified → active；失败/取消保留旧 active；原子切换后撤销旧版本。不同 provider 或外部稳定主体绝不自动合并，即使昵称/邮箱相同。刷新失败返回 auth_required，不改用另一付费身份、不自动转路由。重启后的 pending 按过期/配置版本作废；不重用一次性挑战。

验收：`R13-CORE-005/006/007/008`；当前认证基线继续执行 `RSTRBOT-CORE-17`。

## D03 会话、模型、工具循环与预算（RB-008/023/024/025/026/028/040）

运行输入是会话 ID/generation、用户内容、获准附件引用、模型/Agent 选择、幂等键和有限运行限制；返回持久 `run_id`、接受状态、事件游标及当前可读投影。状态沿用 queued → running → completed/failed/cancelled/interrupted/unknown；只有结构化且通过 schema/授权的工具调用能执行。模型只写工具名的文本保持文本。每个工具调用 ID 与结果配对，稀疏片段按供应商定义组装；完整性验证失败不得执行半个 JSON。

模型往返保留有来源的 provider_state、工具 ID、签名域、附件类型和实际用量；不能把供应商 A 的私有签名搬给 B。路由计划先验证能力（文本/工具/图片/音频/视频/流/上下文大小）和计费授权，再选候选；能力缺失返回 capability_unavailable，不能用无声明的字符串转换假装成功。路由输入顺序固定，记录每次选择原因及配置摘要。

默认不自动重试外部请求。未来 opt-in 重试策略需给 `max_attempts`、允许错误集合、总截止时间与预算；总 attempt 计数包含重连、供应商回退及 SDK 内尝试，不能分层相乘。只有“可证明未发送”或获准的纯读/远端已验证幂等”可自动重试；模型已输出/usage 未知/工具已执行后失败，不静默续为新尝试。允许用户明确创建新 run，但显示上一 run 和可能的额外费用，不覆盖旧记录。

本地权限、参数、幂等/消息冲突和持久化错误属于 core admission/persistence，不能包装成 provider 失败触发模型/供应商切换。先持久接纳规范化消息及意图，再发模型；脱敏日志不得改变业务幂等摘要。真正上游可重试错误才进入已批准且有界的候选链，每次attempt/用量单独归因。此规则纳入 OC-177909 历史线索，验收 `R13-CORE-039`，并不判定其上游当前实机状态。

步骤、总工具数、同签名无进展数与纠错次数分别计数；同工具/参数/结果反复出现达到上限，以 `no_progress` 完成失败事实。到达工具上限后最多一次显式 `tools_disabled` 收尾模型请求，仍消耗预算且必须满足剩余截止；没有预算则以已知结果终止，不伪造自然语言模型输出。取消穿过慢钩子/等待审批/队列/模型/工具；迟到消息不可写回新 generation。

预算账本按主体、工作区、run、attempt、provider、price_revision 归因，金额使用整数微美元；预留与准入原子。缺 usage 或 price 为 unknown/null；外部供应商超出估值仍如实记账并报警，不能为了“硬限额达标”丢掉账单。若供应商无法给可约束上限，严格成本模式拒绝调用；允许估算模式须显式展示保证范围。失败、取消、缓存读取、模型发现可能的供应商费用、重排、嵌入、快速决策和后台总结都列入覆盖度。发现请求不预留当前 RstrBot 生成预算，但供应商可能计费，这个边界不被覆盖。

事件落库使用每个 scope 单调 cursor、event_id 去重、run/generation/attempt 归属。实际执行结束时间和消费者收到时间分别记录；慢消费者是传输/回压失败，不把已完成执行改为超时。终态保存失败应返回实际执行状态加 `persistence:failed`，并保留可核对意图；存储不可用时停止开启新副作用。

停止只取消当前 run；reset 增加投影代次且保留历史；branch 新建会话；删除使后续读取不可见并按保留策略清理。重试是新明确意图，不修改旧历史。分享/嵌入链接是未来单独只读 token，绑定明确内容版本/受众/到期，可撤销，默认不携带写权限或模型密钥。

验收：`R13-CORE-009/010/011/012/013/014`。

## D04 写工具、审批与实际副作用（RB-006/019/029）

当前 read_only 工具准入保持不变。未来工具公开有限 effect 枚举：`read_only / idempotent_write / non_replayable_write`；这是风险声明，不能当授权。调用先解析具体资源与动作，形成不可变 `intent_digest`，绑定工作区/主体/凭据或委托、run/generation、tool/package/instance generation、参数摘要、目标、费用上限及有效期。

审批状态 proposed → approved/rejected/expired/revoked → consumed。批准只能由拥有该资源批准权的主体完成；参数/目标/包版本/授权版本变化使批准失效，不能自动迁移到新调用。审批 UI 必须列真实目标、数据、费用边界和不可撤销后果；模型不能代表用户自批。等待审批不持数据库事务、worker 槽位或开放网络连接。

派发使用持久 `intent_id` 和独立 attempt；先记录 prepared，派发边界记录 sending。已知未发送为 not_sent；远端明确拒绝为 rejected；可靠回执为 accepted；已进入派发而失去证明为 unknown。相同合法幂等键同参数返回原事实，变参数冲突；不同用户合法意图不能被全局文本相同去重。远端幂等支持必须实际验证，发送 Idempotency-Key 本身不构成保证。

撤权发生在批准后、排队后、握手后都要阻止尚未派发的动作；在发送后撤权/取消保留实际回执或 unknown，不自动补发、换会话、换目的地或借其他人凭据完成。核对接口只读取本地记录与明示只读的远端状态；不能用 POST send 当“查状态”。用户若决定再次执行，必须新意图、新批准并显式接受可能重复的风险，原 unknown 保留。

文件工具用获准根目录与对象引用，规范化后再验证真实打开对象；拒绝路径穿越、符号/硬链接逃逸、设备文件和未经批准的网络目标。隔离不可用时执行 capability unavailable，不能降级在宿主运行。具体沙箱由插件合同定义，核心持续拥有授权。

验收：`R13-CORE-015/016/017`。

## D05 知识、索引、摘要与记忆（RB-026/035/036/049）

现有 UTF-8 文本/Markdown 与显式记忆保留。未来导入输入为受权 asset/source 引用、格式、解析器版本、知识库和目标可见范围；输出逐文档任务、失败清单、source_digest、文档版本与 active index generation。文件/URL 导入先验证格式、网络/解码上限；HTTP 错误页不能作为“成功抓取文档”。解析器只访问这次允许的来源，文档中的指令不能授予工具或网络权。

每文档状态 staged → parsing → indexing → ready，亦可 failed/cancelled/deleted。只有原文、分块和必要索引同代齐全后才原子发布 ready；坏文档单项失败不阻塞同批已提交文档。取消清理自己的临时内容，不删别人并发提交。删除先写 tombstone 并撤销检索/下载，再异步清理派生数据；重启任务按文档版本和检查点恢复纯计算，发现版本删除/变化则终止旧任务。

词法/稀疏/向量/重排分别报告 capability 和实际执行路径。向量索引身份由 embedding provider/model/revision、维度、分词/切块策略摘要和 source_version 确定；换模型先新 generation 重建，旧代持续可用或明确 unavailable，不能混合不兼容向量。后台重建失败保留旧代；切换只改变读指针，新旧代资源上限都要计入。

检索先按当前 ACL 筛可用来源，之后打分/融合/重排；如果外部后端不能强制过滤则不发送私有候选，不能“先泄露再过滤”。输出每条引用含 source_id/version、chunk_id、原文字符范围/页码（来源具备时）、标题、解析器与 index generation；对不存在的位置不得编造。重排失败可降级为已经授权的确定候选并标记 degraded，质量指标按固定数据集报告，不用模型自由回答替代引用核验。

永久历史、请求投影、滚动摘要和长期记忆是不同对象。摘要记录 source message IDs/ranges、generation、模型/模板版本和摘要用途；来源修改、删除或权限收缩使相应派生对象 invalidated，在新请求中排除并安排获准重建。自动记忆默认关闭；启用时给明确同意、来源和撤销/删除流程。enabled、archived、deleted、pinned 不能合并：归档不召回但可恢复；删除形成 tombstone；pinned 不受自动衰减删除。共享摘要/记忆不得合成来自个人私聊的内容。

验收：`R13-CORE-018/019/020/021`。

## D06 计划、生成与可靠投递（RB-031/032/038/039/051）

计划输入为所有者、模型/人格快照策略、会话、once/interval/cron、IANA timezone、启停和 `missed_policy=skip`。未来多目标由不可变目的路由列表扩展，每个目标独立意图/回执；默认目标空，不隐式沿用最近私聊。当前接口和 RFB-002 真实只读 preview 保持。

预览只用核心日历引擎计算 next occurrences，输出 UTC、计划地时间、查看者时间、tzdb 版本和暂停状态；无模型、无任务认领、无投递、无预算预留。未知时区拒绝，非选中列表值可自定义但须服务端验证。每日/整点只是 cron 的清楚 UI 构造，不是假前端计算。未来 v2 的缺失日历时刻（春季跳时）跳过；重复墙钟时刻（秋季回拨）选择该配置时刻的最早有效 instant，不能无提示执行两次。当前 v1 实际时间语义保持，通过升级fixtures显式核对差异；同一版本的预览和执行必须同一算法/版本。

每次自动 occurrence 使用 `(schedule_id, schedule_revision, planned_instant)` 稳定身份；手动运行具有不同明确意图，不能回写为某次自动补跑。事务内检查当前 owner 权限和 enabled、持久 occurrence 与 claim，之后才调用模型。已完成 occurrence 在任何次数重启后都不再次执行。进程在认领/派发交界终止时保留 interrupted/unknown，不能无记录消失；先 durable admission 后外部动作。

当前重启语义保持：在途计划禁用并 needs_reconciliation，错过时刻 skip；不能偷偷增加 catch-up。暂停不撤回已经远端接受的动作；显式停止在途 run 走取消合同。未来重新启用先显示未决 occurrence/费用/投递，用户核对后只安排新的未来时刻，不把未知旧操作当新任务补跑。时钟前跳不积累无限补跑，回跳不复用已消费 occurrence。

投递状态独立保存 generation_status、delivery_status、persistence_status、destination/route revision、操作键、remote_receipt_id（有则保存）。新消息上下文只在实际已知发送后以稳定 ID 关联回目标会话；远端 accepted 而记录提交失败时返回 accepted + persistence failed + reconciliation_required。不得因为“整个任务失败”重发。`unknown` 不推断 accepted 或 not_sent，也不借其他会话中继。收到用户立即回复时尽力关联已持久化 outbox 意图与实际回执，缺内容时明确待核对，不编造历史。

独立 MCP 适配器和集成模式共用这些目标授权/意图/回执语义；独立服务具有自己的状态目录和凭据边界，不能假装存在核心用户会话。保留当前 Webhook 文本上限及接受语义，真实平台限制由适配器声明并验收。

本节直接落实 OC-42640/59301 的历史重启场景、OC-91420 的历史跨会话兜底场景；它们是回归目标，不是这些上游项目的现存失败结论。

验收：`R13-CORE-022/023/024/025/026`。

## D07 平台入站、群聊、媒体与文件（RB-006/027/034/037/038/040/050）

平台入站先使用受信适配器固定的连接实例/机器人 ID、连接 generation 和 event_id；平台用户稳定 ID 与核心用户只有经验证绑定才关联。昵称/显示名称/消息里自称用户都不授予权限。`conversation_id` 是核心稳定身份；`origin` 是首次来源；`entry_surface` 是当前查看/发起入口；`delivery_target` 是明确获准路由，四者分离。Web 查看外部会话不改 origin 或路由；模型不能解析 ID 字符串决定目的地。

接收流程 `received → recorded → consumed → answered|silent|failed`。event_id 只在同连接源范围去重；存储入站/消费游标事务提交后才确认消费。门控在昂贵规划前执行，有限规则包括明确提及/命令、允许成员、安静时段、会话速率/预算和静默策略。持续 silent 也推进消费游标并保留获准历史，不伪装 replied；私聊规则独立。自己的送出回声按平台 message_id/发送意图识别并不再次规划，引用自己的旧消息不是自动回声，仍按真实当前入站处理。

平台 polling/reconnect 保存 cursor 和 connection generation。旧连接退出不能清掉新代在线状态；同代失败合并一个有界重连流程，永久认证错误进入 auth_required 等人工修正。队列和积压上限可见，溢出用 backpressure/error，不隐式删除；入站历史和消费状态分开补齐。流式出站按平台限速合并片段，但终尾段和一次终态必须写出或报告失败；不为每 token 刷屏，取消不伪造完整结果。

未来媒体一律使用受权 asset_ref，不直接信任本地绝对路径或公网 URL。asset 归属工作区、主体、资源/会话和版本；二进制原件、缩略图、转换件、转写、引用/转发组件均保留来源及独立 ACL。读取资源不要求启动执行沙箱；执行代码仍另需 sandbox.exec。已消费证据必须是实际 bytes/digest 或模型/解码器读回，返回一个路径不算支持图片/PDF。

上传状态 created → uploading → verifying → published，或 cancelled/failed/expired；按 upload_id/块号/摘要补缺块，完成时验证总长度/摘要/MIME/解码资源。禁止越权续传、同一块摘要冲突、解压穿越/链接/压缩炸弹；无完整验证不得可见 published。取消只清理自己的未发布块，已发布文件不受影响。单文件、单块、总存储、像素/解码时长和运行常驻内存分别有限；能力返回实际限值，未知时拒绝相关操作。

媒体转换输出带类型 `asset_ref`，外部 URL 是受限下载来源而非文件路径，HTTP 错误不得保存为图片。语音生成失败允许用户明确选择文本兜底，保留原失败与可能费用；不能把失败音频附件标为成功。长文分片、引用、图片、转发的有序组件具有 stable component_id；平台不能表示的组件明确 unsupported 或经批准降级，不能无提示丢内容。

验收：`R13-CORE-027/028/029/030/031`。跨入口身份场景对应 OC-84544 历史线索。

## D08 子代理、共享任务与可视化编排（RB-030/033/048/049）

子运行输入为父 run、明确任务、上下文/附件白名单、获准操作集合、预算份额、deadline 和结果目标。核心计算 `child_grant = parent_current_grant ∩ requested_grant ∩ instance_policy`；预算从父 reservation 子划分而不是复制可用额度，深度/数量/并发均有限。父 private 内容不能被移入共享子任务；跨人收集信息只能进入显式共享任务空间，参与者能看到同意范围与撤销入口。

父子状态各自 queued/running/terminal，父保存 child IDs 与汇总原因。前台转后台必须创建显式持久委托，不把旧会话注销后的 run 保活；默认仍由原授权租约限制。父取消/撤权/截止向所有后代传播；已知子结果/费用保存，未决副作用仍 unknown。一个 child 失败可按冻结的 `fail_fast / collect` 策略停止或收集其他已授权结果，不自动换身份/会话再试。重启不重复 spawn，同一派生 intent 读取既有 child；新恢复动作要显式授权。

编排图是版本化 DAG，节点类型有限：read、model、approved_tool、branch、join、subagent、deliver；边带显式数据映射，循环需另行有界迭代节点才能启用，首版不接受任意循环。保存前验证 schema、引用、无环、权限和预算；版本变更不影响已冻结在途图。执行节点具有独立状态/输入输出摘要/attempt/错误，能定位部分完成，未知写节点阻止依赖它的下游自动执行。

调试模式 `validate / simulate / controlled_read`：validate 只检查；simulate 使用注明合成的输出，不访问生产服务；controlled_read 只调用已批准只读夹具/测试环境并计费提示。调试不能调用生产写工具、生产投递或 OAuth 变更，不用“dry_run”字符串绕过效果类型。实际执行需要独立明确动作和当前授权，模型建议不构成批准。

外部工作流/搜索/媒体服务通过受控插件映射输入输出、引用、用量、取消和错误；能力逐项发现，未知字段不能假装支持某供应商协议。通用 MCP 客户端由插件生命周期合同提供，调用仍经过本节同一 operation admission；MCP UI 资源不自动取得执行、网络或父页面身份。

`1.1-draft` 可选 `host.services.v1` broker 仅在核心绑定的 root invocation 内使用同一业务操作。线格式和白名单以 protocol 包为唯一来源；`host.task.submit` 返回 `child_run_id,state`，`host.delivery.prepare` 只保存待批准意图。root结束/撤销/超时使opaque handles失效，旧1.0继续禁止反向请求。broker不得扩大主体权限、代签批准或跳过预算，worker自报workspace不能变更可信上下文。

验收：`R13-CORE-032/033/034/035`。

## D09 运维、配置迁移与多节点（RB-009/010/011/012/013/045/046/051/052）

本地服务与远程服务共用业务逻辑；远程客户端不另起本地核心。数据根由系统路径/显式 portable 目录决定，改变 cwd 不改变数据位置。数据根移动是维护操作：停止执行、取得单实例锁、校验完整清单、复制到新空目录、验证 key/归属/插件数据引用，再原子切换配置；失败保留来源，禁止自动删除唯一副本。升级生成文件不得覆盖数据目录。

当前 SQLite 单核心，PG 也只有单核心验收边界。未来 multi_node capability 仅在 PostgreSQL、所有节点同 schema/协议、共享资产存储、核心可验证 fencing claim、全局幂等与故障验收同时满足后 available。Valkey 不承担唯一租约/权限/预算事实；失联可降级 presence，不能扩大授权。隔离分区中旧 owner 的 fencing token 在数据库提交和任何可控 dispatch gate 被拒绝；无法与远端原子 fencing 的外部副作用仍需 unknown/不重放边界，不宣称分布式 exactly-once。

每节点的时间、队列、数据库、worker、模型、投递和保存耗时分项记录；指标不含消息/密钥，导出脱敏。实时消息与后台索引/媒体使用独立有限队列和每工作区公平额度；控制平面取消/暂停保留服务机会。过载明确拒绝或有界排队，配置无效不给假健康。性能预算待实际测量，固定 1 vCPU/1 GiB 是基准场景而非已达标承诺；核心、子进程、外部依赖分别列占用。

备份、SQLite↔PG、schema migration、恢复隔离与完整外部状态清单依 storage 合同。启动先完成恢复扫描才监听及启调度；迁移失败不半启用。回滚仅在数据版本可逆时允许旧二进制直接打开，否则恢复升级前备份到空目标，不能静默执行降级。CI/三平台签名/安装器是未来独立验收，本次不触发。

验收：`R13-CORE-036/037/038`，`R13-STORE-004` 至 `R13-STORE-013`。所有结论记录真实版本、时间、命令、环境、输入、下游事实及 passed/failed/not_executed/blocked；配方静态检查通过不能转换为软件或竞品通过。

### 非连续来源的派生证据

自动摘要或记忆若合并不同文档或非连续区间，保留每个片段与具体来源、版本和区间的对应，不能将合并文本仅归于第一条引用；无法建立可靠映射时拒绝发布或提升，历史聚合数据不猜测归属。执行根 RSTRBOT-30；当前自动记忆尚未实现。

### 常驻索引读视图

同步词法或未来外部索引须使已发布代次的检索结果与定位表一致；常驻连接/缓存不应停留旧快照造成新文档静默丢失。索引未发布显示处理中；定位不一致时显式降级或失败而非冒充完整结果。运行根 RSTRBOT-31，未实现外部索引不计通过。

RSTRBOT-33：计划本身未来是否还调度与上次运行结果是独立事实；一次性计划的已知失败或取消不能写成 completed。失败后仅能经明确新意图运行，待核对时不得自动派发。

RSTRBOT-34：核对是人确认已检查，不是证明外部执行状态；原 claim、run、计划时刻和确认事实须原子持久化并记录事件。确认保持暂停，重新启用只能显式安排未来时刻；不可把过期一次性计划标成成功或自动补跑。
