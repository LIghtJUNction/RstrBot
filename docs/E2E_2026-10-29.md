## RstrBot：模型拒绝提示修复（配方 1.14）

修复前，上游返回 401 时，浏览器只显示“插件拒绝操作，请检查配置”；同场景 OpenClaw 提供凭据和模型设置的修复方向。修复后，OpenAI 兼容 worker 对上游实际返回的 401、403、429 分别提供安全分类；核心仍返回 HTTP 502，不把上游 401 当作本机登录失效，run 记录保留错误分类。界面根据分类使用当前语言显示凭据、权限或限流提示，前两者提供模型配置入口。未知插件错误保持通用提示；没有收到明确拒绝的网络故障不推断为已拒绝。

实际验证：

- 浏览器中用独立本地 HTTP 夹具逐次返回 401、403、429；三种分类的中文、英文提示均可见，401/403 模型配置入口可达，用户会话保持登录。数据库只读核对了三种失败状态及分类；429 在核心重启、刷新并重开对话后仍显示。401 修复前的旧记录仍能以通用提示读取。
- 403 的模型设置测试走真实 worker，界面显示权限提示，浏览器记录核心响应为 502。夹具的敏感响应体哨兵没有出现在数据库错误字段或所检查的界面文本中；不据此宣称已穷尽所有日志泄露场景。
- 本地 `cargo test -p rstrbot-plugin --test process provider_rejections_remain_classified_and_do_not_expose_response_bodies` 通过：实际插件进程和本地 HTTP 端点对发现、测试、生成三种方法各测试 401、403、429、500，确认分类和不透传响应体。

## CMP-02：会话模型恢复修复（1.18）
