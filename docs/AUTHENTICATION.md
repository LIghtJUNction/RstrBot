# 账户、邮箱、Google 与 Passkey

适用于 RstrBot 0.2.0。此版本在原有密码账户上增加经过验证的邮箱、Google 账号绑定和多枚 Passkey。现有账户、工作区与私有资源权限继续使用同一套服务端授权。

## 管理员先配置什么

打开侧栏的 **账户与安全 → 认证与邮件**。只有实例管理员能读取和保存这份配置；工作区管理员没有这项权限。保存、发测试邮件、发起邮箱换绑和管理登录凭据，需要最近五分钟内用密码或 Passkey 确认身份。邮箱链接确认本身使用十五分钟有效期与原会话绑定，不要求点击时仍处于原来的五分钟窗口。

### 1. 设置固定的访问地址

线上填写实际的 HTTPS 源，例如 `https://bot.example.com`，不附加路径、查询参数或片段。本机开发使用 `http://localhost:8787`。RP ID 使用对应主机名，例如 `bot.example.com` 或 `localhost`，不带协议、路径和端口。

Passkey 的凭据与 RP ID 关联；本版只接受与访问地址完全一致的 RP 主机名。`127.0.0.1` 可以用于本机普通访问和邮件测试，但当前 WebAuthn 库不接受 IP 形式的 RP，因此要测试 Passkey 请从 `localhost` 打开页面。

**实例中任一账户已有 Passkey 时，系统拒绝修改源地址与 RP ID，源地址的协议或端口也不能改变。** 请在开始绑定凭据前选定正式地址；迁移域名需要先保证所有相关账户的备用登录方式可用，再移除实例中全部旧站点凭据并在新地址重新绑定。仅删除管理员自己的凭据不足以解除锁定。本版不提供跨 RP 的凭据迁移。

远程部署仍需要 HTTPS 反向代理。设置 HTTPS 公开地址会让会话 Cookie 使用 `Secure`，但不会让 Rust HTTP 监听端口自动获得 TLS。代理必须保留实际的 `Host`，并限制核心监听端口的直接访问。详见 [运维说明](OPERATIONS.md)。

### 2. 配置发信服务

填写 SMTP 主机、端口、发信地址和显示名称；需要认证时同时填写用户名与密码。支持：

| 模式 | 连接行为 |
| --- | --- |
| TLS | 建立连接时立即使用 TLS，校验服务器证书 |
| STARTTLS | 必须成功升级到 TLS 后才发送认证信息或邮件，不能静默降级 |
| 本机中继 | 只接受 `127.0.0.1`、`::1` 等字面 loopback 地址；用于本机邮件中继和测试 |

先保存，再填写接收地址并使用“发送测试邮件”。成功表示 SMTP 服务已接受邮件，不保证最终收件箱投递。邮件服务商提供的参数、授权密码与发信域名配置需要由部署者准备。

SMTP 密码和 Google 客户端密钥使用安装实例的 `secrets.key` 加密后存入数据库。页面只显示是否已配置；再次保存时，空白密钥输入表示保留原值，明确清除才会删除。修改 SMTP 主机、端口、传输模式、用户名，或 Google 客户端 ID 时，必须重新填写相应密钥或清除，避免把旧密钥自动转发到新目标。

### 3. 配置 Google 登录

按照 [Google OpenID Connect 文档](https://developers.google.com/identity/openid-connect/openid-connect) 创建 Web 应用的 OAuth 客户端，并配置同意屏幕、受众和测试用户等项目设置。在 Google 控制台登记页面显示的完整回调地址：

```text
https://bot.example.com/api/v1/auth/google/callback
```

本机可以使用与配置完全一致的 `http://localhost:<端口>/api/v1/auth/google/callback`。协议、主机、端口、路径必须匹配。将 Client ID 和 Client Secret 填入 RstrBot 并启用；密钥不会发送到前端，也不会放入跳转 URL。

首次使用时，先用已有 RstrBot 账户登录，在 **账户与安全 → Google** 显式绑定 Google 账号。以后可以在登录页选择 Google。当前实例保持管理员创建账户的模式；未知 Google 身份不会自动注册本地账户，也不会因邮箱相同而合并账号。

身份绑定采用 Google 的稳定 `sub`，Google 邮箱仅作为显示信息。它不会自动成为 RstrBot 已验证邮箱，也不会自动获得密码找回权限。代码采用 authorization code、PKCE S256、nonce、一次性 state 和独立的浏览器绑定 Cookie，并在服务器验证签名、issuer、audience、azp 和有效期。

Google 登录可以建立正常的 RstrBot 会话。要修改安全设置，仍需用本地密码或已绑定 Passkey 再确认一次；不会假装 Google 重新签发一个 ID Token 就等于用户刚刚输入了密码或使用了硬件凭据。Google 官方说明，Google 账号会话与应用会话是不同事件，且不支持由应用强制发起 Google 账号重新认证；参见 [Security bundle / Authentication time](https://developers.google.com/identity/siwg/security-bundle)。

## 用户如何配置邮箱

在 **账户与安全 → 邮箱** 输入地址并发送验证邮件。页面不显示验证令牌；邮件中的链接采用 URL 片段，避免令牌进入普通 HTTP 查询和服务日志。

请在发起操作的同一浏览器、同一登录会话中打开链接，并点击确认。链接有效期为十五分钟，只能成功消费一次；退出登录、改密码、会话过期后不能继续使用。不同浏览器中登录同一账户，也不能代替原会话完成该次绑定。

邮箱验证成功后，可以用该地址和原密码登录。更换邮箱时，旧邮箱保持有效，直到新地址确认成功。旧的密码重置链接会随邮箱变更失效；邮箱和其他账户的用户名、已验证地址不能发生别名冲突。

发送验证邮件有每账户一分钟冷却、每小时三次和每日五次上限，公共认证端点还有独立的速率与并发限制。失败后不要依靠自动重试不断发送；页面会显示实际错误。

### 忘记密码

配置发信服务后，登录页提供找回密码入口。只有显式验证过的邮箱可以接收重置链接。未知邮箱、触发账户投递冷却或限额的地址和正常申请都收到相同的接受结果；该结果不证明账户存在或邮件已送达。公共认证入口的全局速率或并发额度耗尽时仍返回 429，请按页面提示稍后重试。

重置链接有效期十五分钟。提交新密码时，服务端检查邮件发出时的邮箱版本与密码版本，防止旧链接覆盖后来的变更。成功后撤销账户的全部登录会话和待完成认证挑战。重置不会解除 Google 或 Passkey 绑定；用户仍可使用这些已绑定方式登录。

本机管理员仍可采用 [运维说明](OPERATIONS.md) 中的本地账户救援方式。它需要控制服务的数据目录，不是公开的 HTTP 重置入口。

## Passkey：物理密钥与云端同步

选择 **账户与安全 → 通行密钥 → 添加**，填写便于辨认的名称，例如“随身安全密钥”或“个人手机”。浏览器和操作系统负责显示可用的凭据选项。

| 选项 | 用途与实际边界 |
| --- | --- |
| 自动选择 | 不强制平台附件类型，由浏览器提供设备凭据、安全密钥或其他受支持方式 |
| 安全密钥 | 向浏览器提供物理密钥偏好；密钥必须支持 FIDO2 用户验证，例如 PIN 或生物识别 |
| 此设备 | 向浏览器提供本机设备凭据偏好，具体保存位置由系统的凭据提供方决定 |
| Android Google Password Manager 兼容模式 | 使用 WebAuthn 库提供的专用兼容流程，显式选择且仅在 Android 浏览器开放 |

所有默认凭据都会要求用户验证。只有按一下触摸按钮、无法完成用户验证的旧 U2F 密钥不作为独立的无密码登录方式。本站只保存验证用的公钥和凭据元数据，不接触私钥，也不负责云端同步私钥。

服务端不把厂商名称当成可信身份。页面的“可同步／已备份”等状态来自已验证的 WebAuthn backup flags；不能据此推断是某一家云服务。浏览器偏好也不保证最终选中的认证器类型。

支持同一账户绑定多枚凭据，每枚都有独立名称、创建时间和最近使用时间。本版使用 **先输入用户名或已验证邮箱，再选择 Passkey** 的登录流程；没有承诺无用户名自动填充或跨 RP 登录。

### 重命名、删除与换绑

- **重命名**仅修改显示名称，不改变凭据密钥。
- **添加**不会影响已经存在的其他凭据。
- **换绑**先创建并验证新凭据，成功后才在同一数据库事务里撤下旧凭据。在提交换绑前取消，或新凭据验证失败时，旧凭据仍然保留。提交后关闭页面不能撤回已经成功的服务端事务；网络中断时应重新读取凭据列表确认结果。
- **删除／换绑成功**会使旧凭据及其签发的会话失效；如果当前会话原本由该旧凭据登录，可能需要用新凭据或密码重新登录。

服务端会检查凭据归属、当前会话、近期认证和配置版本。凭据删除后即使相同 credential ID 再次注册，也不会复用旧版本号，因此先前已经开始的认证请求无法恢复被撤销的身份。账户不能通过删除操作失去最后一种登录方式。

## 升级与备份

0.2.0 启动时在事务内将 schema 1 升级为 schema 2，保留现有账户、会话和工作区。新增表保存身份绑定、近期认证和限时挑战；原始设计包不作修改。

新导出格式是 `rstrbot-db-v2`，保存已验证邮箱、Google 绑定、Passkey 公钥状态和加密的认证配置。会话、认证挑战、邮件令牌与发送限流状态不进入备份。旧版 v1 备份仍可导入并升级到 schema 2；恢复继续进入 quarantine/recovery 模式。

升级前保留数据库备份以及单独保护的 `secrets.key`。升级后的数据库应由支持 schema 2 的程序读取；不能把旧二进制直接当作数据库降级方案。

## 验证范围

测试入口和实际结果见 [0.2.0 改进报告](IMPROVEMENTS_0_2_0.md) 与 [验证回执](evidence/v0.2.0/)。测试使用真正的本机 HTTP/SMTP、SQLite/PostgreSQL、Chromium WebAuthn 虚拟认证器及真实签名的合成 OIDC token。

这些结果验证协议处理、UI 行为、数据库原子性和失败边界。真实 Google 项目、真实邮件服务商、实体安全密钥、手机上的跨设备流程与云账户同步仍需要在部署环境中验收；自动化中的“同步”测试仅指 Chromium 的 backup eligibility/state 标志与相应的凭据流程。
