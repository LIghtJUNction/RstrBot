## 使用规则

- 原用户可见行为和具体边界继续有效，除下表明确重设计/替换者；实现时不得只测 RB 大项而忽略所承接子项。
- 原内部类名、库名和路径不约束新实现。可选平台/供应商在其能力实际交付时完成相应验收。
- JSON 附件包含原始完整表、每条原编号/描述/验收/限制/来源，以及新的归属；无需旧源码才能恢复需求。
- 所有 RstrBot 实现状态为未开始。旧阶段测试、上游合并、需求文档完成都不等于新产品完成。

## 明确的范围变更

- **R004**：保留数据库并发和资源验收；原 MySQL 评估候选由本轮明确的 SQLite/PostgreSQL 双支持替代，不承诺 MySQL。
- **R021**：发布身份迁移和审核状态可由可选目录服务承担，不再以中心插件云为安装前提。
- **R023**：分类、来源、搜索和支持平台保留；市场作为可选索引，直接来源安装必须可用。
- **R029**：保留批量管理和来源回退；不要求单一中心市场。
- **R104**：Windows 原生隔离保留为平台验收；实际机制由可靠维护方案选择，无法隔离时不回退宿主。
- **R141**：持续语音交互作为可选后续能力，基础语音与媒体仍需满足正确性门槛。
- **R142**：按长度选择流式/完整回复作为可选策略，不影响完整流式实现。
- **R174**：可分享或嵌入入口使用可撤销独立范围，不默认为公开工作区。
- **R187**：多节点需 PostgreSQL、共享资源、认领和故障恢复验收，不因启用 Valkey 自动宣称支持。
