## MAI-01 · 消息幂等与聊天页韧性

来源：[MaiBot #2292 — [Bug] WebUI「麦麦聊天」刷新后必崩（React #185）：同一 message_id 重复入库导致虚拟列表 key 冲突](https://github.com/Mai-with-u/MaiBot/issues/2292)。状态：closed / completed；创建：2026-10-27T11:58:21Z；更新：2026-10-27T16:33:18Z；关闭：2026-10-27T16:33:18Z。以上 GitHub 时间为 UTC。

**用户问题。** 报告者描述同一命令消息重复入库，刷新读取历史时聊天列表崩溃；清缓存与重启无效。

**证据与结论边界。** 正文含复现步骤、数据库对照与页面错误；timeline 由提交 bd4af5b719175ab7ceec80bae781b4ce57af71bf 关闭。提交说明修复权限拒绝消息重复存储与聊天列表更新，并加入回归测试。本研究未运行该提交。 证据等级：有关闭修复提交；运行效果未独立验证。

**RstrBot 需求（本次推导）。** 对工作区、适配器实例、平台会话和上游事件标识建立幂等边界；区分上游消息 ID 与本地记录 ID。聊天页容忍历史重复或损坏，并提供诊断、导出和仅修复受影响会话的入口。

**可观察验收。** 同一事件重复投递 100 次，仅形成一个逻辑消息且不重复执行工具或发送回复；含重复历史的会话刷新后仍可浏览；SQLite 与 PostgreSQL 行为一致。

相关结论来源：[1](https://github.com/Mai-with-u/MaiBot/commit/bd4af5b719175ab7ceec80bae781b4ce57af71bf)。

## MAI-02 · 可恢复的会话摘要

来源：[MaiBot #2286 — [BUG] 聊天回想／滚动上下文摘要未持久化，重启后无法恢复](https://github.com/Mai-with-u/MaiBot/issues/2286)。状态：open / 无关闭原因；创建：2026-10-26T15:36:58Z；更新：2026-10-26T15:43:13Z。以上 GitHub 时间为 UTC。

**用户问题。** 用户希望服务重启后继续接上已有约定、背景与进展，不能仅恢复最近原文而丢失滚动摘要。

**证据与结论边界。** 报告者给出观察与固定提交源码链接，并主动说明没有在每个最新分支部署后重启验证。当前 open、无评论；属于具体设计缺口报告，不能写成已独立复现。 证据等级：报告者源码分析与使用观察；无维护者确认。

**RstrBot 需求（本次推导）。** 把有效摘要、对应原文范围、版本、生成信息与会话游标作为持久状态；区分短期上下文压缩与长期知识检索；摘要失效、重建及来源可在界面检查。

**可观察验收。** 生成摘要后正常重启和故障重启，均恢复最后一个已提交的摘要及一致游标；不重复摘要同一原文，不因重启越过用户遗忘或删除设置。

## MAI-03 · 可扩展的发言门控与静默消费

来源：[MaiBot #2276 — [Feature] 为 MaiBot 普通群聊动态门控提供通用插件 Hook（maisaka.turn_trigger.evaluate）与静默已读游标推进](https://github.com/Mai-with-u/MaiBot/issues/2276)。状态：open / 无关闭原因；创建：2026-10-26T06:10:07Z；更新：2026-10-26T06:10:07Z。以上 GitHub 时间为 UTC。

**用户问题。** 插件希望在昂贵的规划调用前决定是否介入；一直不发言时，未读消息不应不断堆积并反复参与判断。

**证据与结论边界。** 开放功能请求，描述现有 hook 时机过晚、缺少调度信息以及静默消息游标不前进。正文引用其他讨论，但本研究未将该引用当作已核实的维护者认可。 证据等级：有场景和提案的功能请求；无评论。

**RstrBot 需求（本次推导）。** 提供带版本的事件准入扩展点，表达处理、延后、仅记录和拒绝等结果；“已接收、已消费、已回答”分别记录。插件只能在授权会话范围内修改调度决策，且有超时和失败策略。

**可观察验收。** 连续 1000 条无需回复的消息不触发昂贵模型且内存队列有界；已消费游标推进；随后明确提问仍获得需要的上下文；未安装门控插件时无需启动语言运行时。

## MAI-04 · RAG 导入的坏记录隔离

来源：[MaiBot #2268 — bug(A_memorix): 单条 77k 字符段落超出 embedding 输入上限，向量重建与恢复探测被永久卡死、双池始终降级](https://github.com/Mai-with-u/MaiBot/issues/2268)。状态：closed / not_planned；创建：2026-10-25T16:44:15Z；更新：2026-10-25T16:44:23Z；关闭：2026-10-25T16:44:23Z。以上 GitHub 时间为 UTC。

**用户问题。** 报告者称一个超过嵌入模型输入上限的文档段落，使整批向量重建及恢复探测重复失败，其余有效记录无法前进。

**证据与结论边界。** 正文有长短输入对照与复现步骤。该 issue 由模板机器人自动关闭，state_reason 为 not_planned；这不表示维护者已修复、否认或评估了技术问题。 证据等级：详细报告；流程性自动关闭；未独立复现。

**RstrBot 需求（本次推导）。** 导入前按实际模型限制分段并保留来源；批任务支持部分成功、持久检查点、永久失败隔离和可见重试状态；能力探测与用户文档处理分开。

**可观察验收。** 混入一个超长或不可解析文档时，其余有效文档完成索引；失败条目显示原因并可重试或删除；重启后不从头循环；不偷偷截断而丢失未告知的内容。

## MAI-06 · 长期记忆保留和真正恢复

来源：[MaiBot #2259 — [BUG] 记忆演化默认 half_life_hours=24 过于激进：3 天未召回即永久归档，人物画像大面积失真](https://github.com/Mai-with-u/MaiBot/issues/2259)。状态：open / 无关闭原因；创建：2026-10-24T15:11:55Z；更新：2026-10-24T15:11:55Z。以上 GitHub 时间为 UTC。

**用户问题。** 用户反馈不常联系者的人物记忆随时间衰减而消失，恢复归档后仍不参与检索，界面与实际有效状态不一致。

**证据与结论边界。** open，无评论。正文包含数据计数和恢复观察；不能据此推广为所有部署的现状，也不沿用其“永久删除”等混合表述。 证据等级：具体用户报告；无维护者确认。

**RstrBot 需求（本次推导）。** 明确区分检索权重下降、归档、停用与删除；长期事实默认不因暂未召回而永久删除。支持用户固定、查看来源、纠正、导出及删除；恢复必须恢复可见性和检索资格。

**可观察验收。** 推进模拟时间不会删除固定事实；归档、恢复后查询和人物页一致；所有自动保留策略可解释并有预览；删除按工作区与主体范围传播到摘要和派生索引。

## MAI-07 · 身份消歧及多用户隔离

来源：[MaiBot #2257 — [BUG] 人物画像按名字查询会命中错误的人：别名不参与解析、群名片子串优先、搜索结果无排序](https://github.com/Mai-with-u/MaiBot/issues/2257)。状态：open / 无关闭原因；创建：2026-10-24T15:07:07Z；更新：2026-10-24T15:07:07Z。以上 GitHub 时间为 UTC。

**用户问题。** 按昵称查询可能命中包含该昵称的另一人；别名设置若只影响显示而不影响解析，用户会得到错误画像。

**证据与结论边界。** open，无评论；正文给出同名子串冲突的步骤与解析路径分析。本文件不复制其中真实昵称、平台账号或人物记录标识。 证据等级：具体用户报告；无维护者确认。

**RstrBot 需求（本次推导）。** 身份以工作区、平台、账号及稳定主体标识定位，昵称只作搜索字段。精确匹配与模糊候选清晰区分；多候选必须消歧，禁止凭昵称自动把私人记忆或发送目标合并。

**可观察验收。** 同名、近似名、改名及跨平台同名样本不串人；模糊结果需选择；普通成员不能通过猜测 ID 或搜索别名读取另一工作区资料。

## MAI-08 · 插件启动生命周期和 MCP 可诊断性

来源：[MaiBot #2260 — [BUG] MCP stdio 连接超时硬编码 30s 且失败后不重试，uvx 类 MCP 首次连接必然失败](https://github.com/Mai-with-u/MaiBot/issues/2260)。状态：open / 无关闭原因；创建：2026-10-24T16:25:28Z；更新：2026-10-24T16:25:28Z。以上 GitHub 时间为 UTC。

**用户问题。** 使用现代包启动器的 MCP 冷启动可能较慢；一次建连超时后永久停在失败状态，用户修改的读超时又不控制启动超时。

**证据与结论边界。** open，无评论。报告含冷、热启动对比与配置分析；其中时间是报告者环境结果，不是通用性能基线。 证据等级：详细用户观察；无维护者确认。

**RstrBot 需求（本次推导）。** 把安装、启动、握手、请求、空闲及退出期限分开；安装与解析依赖可观察。对可重试失败有限退避，允许手动重试；保留脱敏标准错误、当前阶段和最近错误，支持取消及进程树回收。

**可观察验收。** 慢启动测试桩在配置期限内可成功；过期后无遗留进程，重试有次数上限；同配置也可重新连接；安装失败与握手失败在界面中清楚区分。

**用户问题。** 群聊可用的提及或表情回应能力被用于私聊，导致整段正文发送失败或暴露不可执行工具。

## MAI-10 · Agent 预算与无进展终止

来源：[MaiBot #1710 — [优化]目前planner的提示词对agent能力不强的LLM不友好，导致大量output token浪费](https://github.com/Mai-with-u/MaiBot/issues/1710)。状态：closed / completed；创建：2026-05-17T03:11:38Z；更新：2026-08-07T06:07:51Z；关闭：2026-08-07T06:07:51Z。以上 GitHub 时间为 UTC。

**用户问题。** 用户反馈模型在普通文本中写工具名而没有产生结构化调用，规划多轮重复分析，成本增加却没有有效输出。

**证据与结论边界。** 多个参与者描述类似情况；COLLABORATOR 于 2026-06-08 称在 dev 优化调用能力。issue 完成关闭，但后续有偶发报告；费用和倍率是用户自报。 证据等级：多方报告及维护协作者优化说明；未独立基准。

**RstrBot 需求（本次推导）。** 引擎应识别无结构化调用、连续无进展、重复工具与预算耗尽；普通文本不是执行指令。为任务、用户、工作区设轮次、耗时和费用边界，呈现规划、检索、工具与生成各阶段用量。

**可观察验收。** 持续只输出工具名的模型不能无限循环，也不会执行该文本；到达边界后停止并显示原因及部分结果；用户取消后不继续计费发起新请求。

## MAI-15 · 媒体规范化与失败任务治理

来源：[MaiBot #2293 — [Bug] 图片记忆无法收录 GIF：MIME 白名单与多帧检查双重拒绝（附补丁）](https://github.com/Mai-with-u/MaiBot/issues/2293)。状态：open / 无关闭原因；创建：2026-10-27T16:07:52Z；更新：2026-10-27T16:07:52Z。以上 GitHub 时间为 UTC。

**可观察验收。** 静态图片与 GIF 测试集按声明能力导入；不支持的文件显示原因与可选转换；坏文件不能卡住其余任务；衍生内容仍可追溯到原始来源。

## 对新蓝图的综合影响

1. **状态必须能恢复。** 已接收消息、已消费游标、生成摘要、计划任务与外发结果是不同状态，需可解释、可重放、可去重。展示成功不能替代真实投递或持久化成功。
2. **重试必须能停。** 错误分为暂时失败、永久不支持、预算耗尽和用户取消；不能把坏文档、冷启动失败、无效工具调用都当成无限重试机会。
3. **权限与能力需在执行时检查。** 昵称不是身份，私聊不是群聊，模型声称可调用的工具也不等于当前用户和会话获准调用。
4. **个性与效率可配置。** 陪伴型主动参与和任务型助手应是不同预设；群聊与私聊、不同工作区各自覆盖，不把某一种拟人行为固化到 Rust 核心。
5. **插件化需要生命周期。** 安装、依赖准备、启动、握手、提供能力、降级、重连、退出必须能被看见；后台学习和索引任务不能把实时收发阻塞。
6. **数据库差异不能改变产品承诺。** SQLite 与 PostgreSQL 必须共用隔离、幂等、恢复和删除语义的验收；Valkey 可加速，但不应成为未声明的唯一事实来源。

这些推导需要与其他项目研究和用户明示需求合并。未阅读的 issue 不作结论，研究不宣称覆盖 MaiBot 全部用户需求。
