# RstrBot 前端产品设计

设计基线 1.0 · 2026-10-28

这是界面蓝图与验收目标，尚未制作可运行页面或完成浏览器视觉验收。参考项目只提供设计方法；RstrBot 的主体、构图、文案和产品流程重新设计。

## 1. 设计本质

界面首先帮助用户看懂“谁在做什么，做到哪了，我能如何处理”。粒子雕塑用于建立识别度；聊天、操作和错误信息始终是可阅读、可选择、可访问的正常页面内容。

采用 particle-sculpture-skill 的方法：先确定表达与主体，再确定构图、色彩、物体动作、镜头、转场和交互；不把某个示例字体、配色、全屏旋转或卡片布局当成强制模板。[设计方向](https://github.com/LIghtJUNction/particle-sculpture-skill/blob/2a6f5ac818f722be95ff12aca5f807adf593b135/references/design-directions.md)

## 2. 三个方向与本轮选择

| 方向草案 | 构图、主体、字形与动作 | 适用与代价 |
| --- | --- | --- |
| **A：墨色折线，推荐并采用** | 左侧短标题与清楚动作，右侧粒子组成有厚度的折线雕塑；中性无衬线正文、少量等宽状态；炭黑/纸白配少量香槟色；固定镜头，局部缓慢展开 | 安静且有品牌识别，适合长期使用；雕塑必须保持可辨认，不能变成随机点云 |
| B：可见结构 | 浅色工作纸、对齐标尺、正交投影的模块化桥接形体；等宽标注、部件分层展开 | 适合开发者和系统说明；容易显得过于工程化，需避免虚假指标和无用网格 |
| C：轻巧拼合 | 较明亮留白、错位排版、几块有体积的几何体；清晰粗标题、受控的部件组合 | 亲近非技术用户；长期后台需要减少饱和色和动作频率 |

三个方向在空间关系、字体层级、主体和运动方式上不同。本轮继续 A，无需等待审美问卷。后续只有用户提出方向变化才重选。

## 3. 品牌展示区

### 3.1 表达与场景

表达：把分散的消息、工具和资料组织成可控制的工作。主体为原创折线结构，视觉上可联想到 R 的转折，但不使用难以辨识的立体字来承担正文。

默认固定镜头；物体在静止形态保持清楚的重心与轮廓。局部折线以缓慢、可暂停的方式展开并回到稳定位置，表达“接入—处理—返回”。没有真实数据时不标注实时节点数或用量。

首页主动作依用户状态显示“建立工作区”“进入工作区”或“连接服务器”，另有简短说明与帮助。文字先出现，粒子资源稍后加载。用户正在登录、验证连接或处理错误时不播放夺取注意力的转场。

桌面启动页、空工作区欢迎页和产品介绍可复用同一品牌组件，控制密度和尺寸。业务页面只保留静态标识，不持续渲染全屏粒子。

### 3.2 动作约束

物体动作、镜头、场景进度和指针反馈分开设置。默认指针反馈关闭或仅有轻微局部偏移，触摸滚动与缩放始终保持原生行为。切换主题直接更新正文颜色，雕塑可以短暂过渡，但不能经过不可读的中间配色。

默认采用静止形态加局部轻动；不做自动完整旋转。页面切换通常直接完成，不每次散开重组。动画可从当前状态被打断，不重新播放长开场。减少动态效果模式完全停止装饰性位移和持续旋转，提供静态几何替代。

粒子只是材质表达。需要真实玻璃、折射或体积光时必须另行评估渲染方案与预算；不把普通点的叠加叫物理光照。[色彩和动作方法](https://github.com/LIghtJUNction/particle-sculpture-skill/blob/2a6f5ac818f722be95ff12aca5f807adf593b135/references/color-and-motion.md)

## 4. 信息架构

应用始终显示当前工作区及用户身份，切换后取消旧页未完成的请求，旧结果不得覆盖新工作区。全实例管理使用独立入口与明显上下文，不和工作区管理混排。

| 一级区域 | 内容 | 默认第一动作 |
| --- | --- | --- |
| 对话 | 私有/共享会话、搜索、分支、附件 | 新建对话或继续最近会话 |
| 运行与收件箱 | 正在运行、待确认、待核对、后台完成 | 处理需要用户决定的事项 |
| 知识与记忆 | 文档库、导入状态、引用、可编辑记忆 | 上传资料或查看记忆来源 |
| 计划任务 | 下次触发、时区、历史、多目标结果 | 新建任务并预览时间 |
| 机器人与渠道 | 平台连接、账号、投递路由、会话策略 | 接入渠道或恢复失效连接 |
| 模型 | 可用模型、协议能力、凭据使用范围、用量 | 测试当前连接的实际能力 |
| 插件 | 已安装包、工作区实例、运行时、更新与恢复 | 安装或配置一个插件 |
| 管理 | 成员、权限、预算、配置、审计、备份 | 根据当前角色呈现可用操作 |

窄屏将主导航收进可键盘访问的抽屉，保留当前标题、工作区切换和常用动作。复杂表格改成可展开的列表，不能简单缩小字体塞入整张桌面表格。

## 5. 核心页面交互契约

### 5.1 首次设置

提供单线流程：用途 → 管理员 → 数据库 → 可选服务 → 工作区 → 检查结果。数据库页并列展示 SQLite 与 PostgreSQL，说明运维和并发差异。Valkey 放在可选加速页，关闭时明确“基础功能仍可使用”，不把它伪装成必选依赖。

数据库连接测试显示正在验证的阶段；失败保留输入和已完成步骤，密码字段不回显或写入日志。数据目标已有内容时先识别再提供迁移/连接选项，不能一键覆盖。最终页面显示选定数据位置、备份入口和首次使用动作，不暴露无关内部实现细节。

### 5.2 聊天

消息正文优先，工具过程默认折叠为简短阶段，可展开查看具体输入摘要、输出、耗时与授权依据。引用可跳到获准文档片段，附件有格式与可用状态。

“停止”在生成和排队时始终可达；“新会话”“重置上下文”“删除历史”有各自解释。编辑后生成新分支，旧分支可回看；模型切换显示会影响的能力，不无声丢掉工具或附件。

出错时显示可以执行的下一步：调整配置、重试生成、核对已执行操作、下载诊断、恢复连接。存在不确定写入时不提供默认的一键整轮重放。模型输出原样作为不可信内容处理，不能注入页面操作。

### 5.3 运行详情

以时间线呈现“接受、准备、模型、工具、投递、保存”，每段显示真实状态。用户看到“已发送，记录保存失败”时，可以核对和修复保存，而不是只看到红色“失败”后再次发送。

会话、来源任务、执行者、模型、工具和收件人是可追溯对象；授权不足时不通过错误提示暴露对方名称。查看者只能读获准部分，不能从诊断页面获得管理员操作入口。

### 5.4 插件管理

区分机器已安装的插件包和当前工作区启用的实例，清楚显示影响范围。列表提供来源、版本、运行时、状态、更新、配置入口和日志。即便加载失败仍能修改配置、重装或回滚。

状态至少包括未安装、下载中、准备依赖、待授权、已安装未启用、启动中、运行中、降级、停止中、失败、待重启。保存配置与运行成功不能共用一个绿色提示。

安装确认说明新增能力、数据访问范围、网络与执行权限、运行时占用。更新仅展示变化，不重复堆砌整个清单。批量操作逐项显示结果与恢复入口，跨页全选范围明确。工作区管理员不能通过安装界面获得宿主软件安装权限。

### 5.5 知识与记忆

上传进度与索引进度分别显示；部分失败保留成功项和失败原因。支持同名覆盖、重命名、跳过，删除前显示引用影响。后台重建期间显示仍在使用的索引版本和新索引状态。

记忆页显示“来自哪里、何时建立、在哪些会话可用、用户是否确认”。降低检索权重、归档、暂停使用、删除和恢复使用不同动作。清除记忆说明会清除的索引与缓存，以及备份保留的现实边界。

### 5.6 任务与平台

日历任务显示时区和接下来触发时间，固定间隔显示起点和错过执行规则。暂停与停止当前运行分开；多目标投递逐个显示已接受/失败/未知。平台被动回复额度、主动发送限制和富消息降级能力直接影响可选项。

机器人重新绑定复用已验证流程，取消不修改旧连接；确认切换前提示在途消息影响。连接“能接收”与“能发送”分别检查，不能只凭 WebSocket 连通显示全部健康。

## 6. 视觉规范

以下是原创候选 token，属于设计值。开发时仍需在真实字体、透明度、错误态和禁用态下完成对比度与视觉检验。

| 角色 | 深色 | 浅色 |
| --- | --- | --- |
| 页面背景 | #121315 | #F7F4ED |
| 次级表面 | #1B1D20 | #FFFFFF |
| 正文 | #F4F1E8 | #1A1B1B |
| 次级文字 | #AAA79F | #5C5D5E |
| 主强调 | #D8B77B | #70501F |
| 细分隔线 | #36383D | #D4D0C7 |
| 键盘焦点 | #E8C78D | #704D15 |

正文优先系统无衬线字体和高质量 CJK 回退；技术编号、耗时使用等宽字体。避免为装饰标题下载大套字体。正文 16px，辅助内容不低于 13px；中文段落行高约 1.6，密集表格可适当降低但保持可扫读。

间距采用 4/8/12/16/24/32/48px 层级；交互区圆角约 8px，面板约 12px。用留白、背景层级和少量边界组织内容，不把每段文字都包一张卡片。主要动作每个区域保持一个显著入口。

普通文字对比度目标至少 4.5:1，大字及必要非文字视觉目标至少 3:1；色彩不是状态的唯一线索。错误同时使用清楚文本与图标。按钮在触摸场景提供至少 44×44px 的可触达区域。[WCAG 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

## 7. 响应式与可访问性

至少覆盖 320、360、390、430、768、1280、1440px 宽度，横屏与短视口单独检查。200% 缩放仍能完成核心流程，键盘焦点不被固定底栏挡住，输入法组合状态不触发错误发送。

重要消息使用适度的屏幕阅读器提示，不能每个 token 都朗读一次。流式滚动仅在用户仍靠近底部时跟随，用户回看历史时提供“有新内容”入口而不抢位置。对话切换保留草稿和阅读位置。

所有功能都有 DOM 操作，Canvas 没有不可替代按钮。图标有可理解名称，弹窗处理焦点进入/退出，关闭与 Escape 行为一致。支持减少动态效果、暂停和静态回退，并测试无 GPU 或渲染初始化失败时的主流程。

## 8. 性能与动画预算

| 范围 | 设计目标 | 降级方式 |
| --- | --- | --- |
| 业务首屏 | 压缩后初始脚本目标 ≤250 KiB，按实际构建统计；粒子、编辑器、图表、语音另行懒加载 | 优先文本、表单、当前列表 |
| 页面可用 | 固定手机档位及受控网络下 LCP 目标 ≤2.5s、交互响应目标 ≤200ms、布局偏移目标 ≤0.1 | 关闭装饰资源，保留所有操作 |
| 粒子规模 | 初始上限桌面 12,000 点、手机 2,500 点，实际根据测量下调 | 静态原创标识，不假称动态效果已展示 |
| 粒子像素密度 | 默认设备像素比上限 1.5，避免高分屏放大开销 | 降采样或静态 |
| 绘制生命周期 | 一个动画驱动者，隐藏、离屏、用户暂停时停止；销毁后无残余回调 | 暂停状态切主题仍更新静态画面 |
| 长历史 | 按需分页或虚拟列表，稳定消息标识，重复记录不使整页崩溃 | 错误项可隔离查看，其他消息仍可用 |

这些数字是起始预算，未实际测量。页面基本可用优先于维持点数或帧率，性能报告同时给出设备、浏览器、主题、场景和测量方式；不能把空白页成绩当成真实聊天页成绩。

## 9. 界面验收场景

1. 首次使用者不读开发文档，完成 SQLite 初始化、连接模型和首次对话；PostgreSQL 连接失败可原路修改且不丢配置。
2. 同一浏览器快速切换两个工作区，旧请求与流不会污染新页面；撤权后不能继续看到事件、预览或搜索结果。
3. 插件配置保存成功但启动失败时，两种状态同时可见；批量更新部分失败可定位到单个插件。
4. 模型回答已投递、保存失败时，界面提供核对与恢复，不诱导重复外部操作。
5. 320px 手机、键盘、屏幕阅读器、减少动画、深浅色均能完成聊天、停止、上传、任务取消和恢复连接。
6. 刷新、断网、浏览器后台恢复、侧栏切换、重复事件和索引重建都有稳定状态，不永久转圈。
7. 真实桌面安装器中完成新建会话、切换工作区、关闭窗口、退出进程和升级；不能仅以 Web 页面测试代替。
8. 粒子静态端点、最宽姿态、中间转场、反向切换和文字放大不裁切主体或遮住主要动作。没有真实预览时交付只能称设计草案。
